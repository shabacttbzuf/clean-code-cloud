# تغليف نظام الويب كتطبيق Android

## القرار المعماري

سيبقى نظام إدارة المطاعم تطبيق ويب واحداً (React + TanStack Start) ومصدراً وحيداً للواجهات وقواعد العمل. تطبيق Android هو حاوية Capacitor WebView فقط، وليس تطبيقاً مستقلاً أو إعادة كتابة بـ Kotlin/Compose.

## نسخة الاختبار الحالية المرتبطة بـ Termux

أُعدّ Capacitor افتراضياً لفتح خادم الويب المحلي على الهاتف نفسه:

- العنوان داخل WebView: `http://127.0.0.1:5173`.
- تشغيل الخادم من مجلد المشروع في Termux: `bun run dev --host 0.0.0.0`.
- المنفذ الافتراضي لـ Vite هو `5173`.
- يمكن تغيير العنوان وقت بناء الحاوية عبر متغير `CAPACITOR_SERVER_URL`.
- عند توقف خادم Termux تظهر صفحة مساعدة محلية بدلاً من شاشة فارغة.

هذه نسخة تطوير واختبار وليست إصدار إنتاج. يجب إبقاء Termux والخادم قيد التشغيل على الهاتف كي يستطيع التطبيق تحميل النظام. العنوان `127.0.0.1` يشير إلى الهاتف نفسه ولا يعمل من هاتف آخر.

## بناء APK

سير العمل `.github/workflows/android-wrapper.yml` يثبت أدوات Capacitor بإصدار ثابت، يفحص TypeScript، يبني الويب، ينشئ مشروع Android مؤقتاً، ثم ينفذ `assembleDebug` ويرفع APK كأثر GitHub Actions لمدة 14 يوماً. لا يضيف ملفات Android مولدة ضخمة أو يغير جداول قاعدة البيانات.

## حدود الأمان

إعداد HTTP و`cleartext` محصوران في نسخة الاختبار المحلية. لا تستخدم هذه الإعدادات في إصدار الإنتاج. عند اعتماد نطاق HTTPS لاحقاً، يجب إزالة عنوان Termux و`cleartext` من إعداد الإصدار النهائي، ثم اختبار الجلسات والروابط والتنقل وService Worker داخل WebView.

## حدود العمل دون اتصال

تخزين واجهة الويب لا يعني أن Supabase أو تسجيل الدخول أو كل عمليات المطعم تعمل دون اتصال. بيانات العمليات المحلية وطابور المزامنة جزء منفصل من المهمة 18. لا تُخزّن كلمات المرور أو مفاتيح الخدمة أو استجابات المصادقة في Cache Storage.
