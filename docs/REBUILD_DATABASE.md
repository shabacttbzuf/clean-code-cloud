# إعادة إنشاء قاعدة بيانات المشروع

## الحالة الحالية

تم تجهيز سلسلة ترحيلات المشروع وفحصها على قاعدة Supabase محلية فارغة ضمن GitHub Actions. نجحت خطوات:
- تشغيل Supabase المحلي.
- تنفيذ `supabase db reset --local` وتطبيق سلسلة الترحيلات كاملة.
- اختبارات المشروع، وفحص TypeScript، وبناء الإنتاج.

**لم يتم الاتصال بقاعدة Supabase بعيدة، ولم يتم تنفيذ أي ترحيل على قاعدة الإنتاج أو على مشروع جديد للمستخدم.**

## مصدر مخطط قاعدة البيانات

- ملفات SQL في `supabase/migrations/` هي مصدر الحقيقة للمخطط.
- يوجد 20 ترحيلاً تاريخياً محفوظاً كما هي، وأضيفت 11 ترحيلاً تصحيحياً جديداً؛ الإجمالي 31 ترحيلاً.
- لا تعدّل ترحيلاً قديماً سبق تطبيقه؛ أضف ترحيلاً جديداً فقط.
- `src/integrations/supabase/types.ts` ملف أنواع مولّد/محدّث، وليس بديلاً عن مخطط SQL.
- `drizzle/schema.ts` معلن صراحة أنه فارغ عمداً، لذلك لا يُستخدم كمصدر للمخطط.
- كان هناك ترحيل Drizzle قديم في `drizzle/migrations/0000_scope_permission_visibility.sql`. نُقلت قواعده إلى ترحيل Supabase رقم 24 في السلسلة، ولا تشغّل ملف Drizzle القديم مرة ثانية بعد تشغيل سلسلة Supabase.

## خطوات إنشاء قاعدة جديدة

1. أنشئ مشروع Supabase جديداً وفارغاً.
2. احتفظ بمعرّف المشروع ورابطه ومفاتيحه في إعدادات النشر السرية. لا تضع مفتاح `service_role` في Git أو في المتصفح، ولا ترسله داخل المحادثة.
3. ثبّت Supabase CLI وسجّل الدخول.
4. اربط مجلد المشروع بالمشروع الجديد:
   `supabase link --project-ref <NEW_PROJECT_REF>`
5. راجع أن المشروع المرتبط هو المشروع الجديد والفارغ، ثم نفّذ:
   `supabase db push`
6. حدّث متغيرات البيئة في منصة الاستضافة:
   - `SUPABASE_URL`
   - `SUPABASE_PUBLISHABLE_KEY`
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` (خادمي فقط، سري)
   - `INITIAL_SUPER_OWNER_USER_ID` (خادمي فقط، مؤقت لتهيئة المالك الرئيسي الأول)
7. أنشئ حساب المستخدم الأول، ثم ضع UUID الخاص به في `INITIAL_SUPER_OWNER_USER_ID`، واستدعِ إجراء تهيئة المالك الرئيسي مرة واحدة.
8. بعد نجاح التهيئة، احذف `INITIAL_SUPER_OWNER_USER_ID` من بيئة التشغيل.
9. أعد توليد أنواع Supabase من القاعدة الجديدة عند الحاجة، ثم شغّل فحوص البناء والاختبارات.

## ملف SQL الشامل

- الملف المجمع: `supabase/COMPLETE_DATABASE.sql`
- قائمة الترحيلات وترتيبها: `supabase/MIGRATION_MANIFEST.md`
- يحتوي الملف المجمع على محتوى الترحيلات الـ31 بالترتيب، وتتحقق اختبارات CI من تطابق قائمة ملفاته مع مجلد الترحيلات.

الملف المجمع Snapshot للمراجعة والاحتفاظ بنسخة واحدة من السلسلة. **المسار الموصى به للتطبيق على قاعدة جديدة هو `supabase db push`** لأنه يطبق كل ملف منفصلاً ويسجل تاريخ الترحيلات. لا تنفّذ الملف المجمع يدوياً ثم تشغّل `db push` على القاعدة نفسها. لم نختبر تشغيل Snapshot كملف SQL واحد مستقلاً؛ الاختبار الناجح كان لسلسلة الملفات الفردية عبر Supabase CLI.

## حدود الاستعادة

إعادة إنشاء المخطط لا تستعيد بيانات القاعدة القديمة. الحسابات، والمبيعات، والمشتريات، والموظفون، والسجلات التاريخية لا يمكن استرجاعها من ملفات الترحيل؛ تحتاج إلى نسخة احتياطية أو مشروع Supabase القديم إن كانت البيانات مطلوبة.
