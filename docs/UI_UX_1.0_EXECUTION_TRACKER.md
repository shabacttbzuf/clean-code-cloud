## قواعد لا يجوز تجاوزها

1. عدم حذف أي ميزة أو مسار قائم.
2. عدم حذف أو تعديل بيانات الإنتاج.
3. عدم تغيير أسماء الجداول أو المسارات إلا لضرورة موثقة وتوافق خلفي.
4. عدم إضعاف RLS أو صلاحيات الخادم أو حماية Super Owner.
5. عدم تعديل أثر العمليات المالية أو المخزنية بسبب تحسين الواجهة.
6. كل زر أو إجراء جديد يجب أن يؤدي وظيفة حقيقية، مع احترام الصلاحيات على الواجهة والخادم وقاعدة البيانات.
7. تجهيز ترحيلات جديدة فقط عند ثبوت الحاجة، وعدم تعديل الترحيلات المطبقة سابقاً.
8. لا تطبيق على قاعدة الإنتاج قبل مراجعة SQL وآثاره وخطة الرجوع.
9. وفق اتفاق سير العمل، تؤجل دورة الاختبارات الشاملة إلى ما بعد اكتمال المتطلبات؛ ويستمر فحص الكود ومراجعة التوافق أثناء التطوير دون إعلان نتائج اختبار لم تُنفذ.
10. لا دمج إلى `main` قبل نجاح الاختبارات الشاملة ومراجعة الترحيلات.

- تحذير أمني: حماية كلمات المرور المسربة في Supabase Auth غير مفعّلة؛ يلزم تقييم وتفعيلها من إعدادات Auth بعد اعتماد الأثر التشغيلي.

- تحذيرات أداء عن سياسات permissive متعددة وفهارس غير مستخدمة. لا تحذف سياسات أو فهارس اعتماداً على التحذير وحده؛ يجب تحليل تداخل الصلاحيات وخطط الاستعلام وأحجام البيانات أولاً.
