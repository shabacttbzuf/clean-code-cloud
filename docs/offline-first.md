# أساس العمل دون اتصال (PWA Offline First)

## ما يعمل حالياً

- بعد أول زيارة ناجحة أثناء الاتصال، يسجل التطبيق Service Worker ويجهّز غلاف الواجهة والموارد الثابتة التي أمكن اكتشافها من صفحة البداية.
- تُخزّن ملفات الواجهة الثابتة من نفس النطاق عند طلبها، وتُستثنى طلبات الكتابة وجميع مسارات Supabase الخاصة بـ REST وAuth وFunctions وStorage ومسارات API.
- عند انقطاع الاتصال، يحاول Service Worker عرض غلاف التطبيق المحفوظ، ثم صفحة توضيح عدم الاتصال إذا لم يكن الغلاف متاحاً.
- يظهر مؤشر اتصال يوضح صراحة أن المتاح دون اتصال هو الواجهة التي سبق تحميلها فقط.

## حدود مقصودة لحماية البيانات

- لا يتم تخزين سجلات المبيعات أو العملاء أو المخزون أو الحسابات أو بيانات الشركات والفروع عشوائياً في Cache Storage.
- لا تُخزّن كلمات المرور أو مفاتيح الخدمة أو استجابات المصادقة أو طلبات التعديل.
- لا يعتبر وجود جلسة محفوظة محلياً دليلاً على أن صلاحيتها ما زالت سارية؛ يجب أن يتحقق الخادم من الجلسة والصلاحيات عند عودة الاتصال.
- لا يمكن تنفيذ عمليات تتطلب Supabase أثناء انقطاع الشبكة بهذه المرحلة، ولا يتم تجاوز RLS أو صلاحيات المستخدم لإظهار بيانات مخزنة.

## ما يتطلب مرحلة البيانات والمزامنة (المهمة 18)

يلزم تحديد قائمة بيانات مسموح بها لكل دور وشركة وفرع قبل تخزين أي بيانات أعمال محلياً، ثم استخدام IndexedDB بمفاتيح نطاق تشمل هوية المستخدم والشركة والفرع، والتحقق من الصلاحيات عند القراءة والمزامنة، ومعالجة تعارضات المزامنة وانتهاء الجلسة. لم تُفعّل هذه الآلية هنا حتى لا يؤدي التخزين العام إلى تسريب بيانات بين الشركات أو الفروع.

## شروط التشغيل

- يجب فتح التطبيق مرة واحدة على الأقل بنجاح أثناء توفر الإنترنت حتى تُحمّل الموارد وتُخزّن.
- يجب تقديم PWA عبر HTTPS أو localhost حتى يعمل Service Worker.
- أول زيارة دون اتصال غير مدعومة.
- نجاح تحميل الواجهة دون اتصال لا يعني أن قاعدة البيانات أو جميع وظائف المطعم تعمل دون اتصال.

## مخزن IndexedDB المرجعي — سياسة الاستخدام

يوفر `src/lib/offline-reference-cache.ts` واجهة تخزين اختيارية لنسخ مرجعية غير حساسة فقط. كل سجل مربوط بمعرّف المستخدم والشركة والفرع، وتنتهي صلاحيته خلال مدة أقصاها سبعة أيام. الأنواع المسموحة محصورة في `catalogue` و`categories` و`settings`، مع فحص متكرر لأسماء الحقول الحساسة ورفضها. يُمسح المخزن بالكامل عند تسجيل الخروج.

قبل استخدام هذه الواجهة في أي شاشة:
1. اجلب البيانات أولاً عبر عميل Supabase المصادق عليه وتحت سياسات RLS.
2. مرر معرفات المستخدم والشركة والفرع الموثقة من سياق الجلسة.
3. تعامل مع النسخة المحلية كبيانات قديمة للقراءة فقط، ولا تجعلها مصدراً محاسبياً.
4. أعد التحقق من الجلسة والصلاحيات عند عودة الاتصال، وامسح النسخ عند تبدل الهوية أو الشركة أو الفرع.
5. لا تخزن سجلات مالية أو رواتب أو بيانات عملاء/موظفين أو مخزون أو مدفوعات أو أسرار.

هذه أداة آمنة اختيارية وليست تكاملاً تلقائياً لكل شاشات النظام. لا توجد مزامنة أو طابور عمليات ضمن المهمة 17؛ ذلك منفصل عن المهمة 18. لا تعتبر اختبارات الشيفرة بديلاً عن اختبار متصفح/هاتف فعلي بعد أول تحميل متصل.
